--------------------------------------------------------------------------------
1. INTRODUCTION
--------------------------------------------------------------------------------
The CHRIST University Regex Chatbot is a modular, rule-based conversational
system built as part of the Advanced NLP curriculum. The chatbot's core design
principle is to perform Natural Language Understanding (NLU) and entity extraction
efficiently using regular expressions and fallback text-similarity algorithms,
avoiding the computation costs and unpredictability of deep learning models.

The chatbot provides instant, accurate information on:
- Admissions and Application Procedures
- Christ Online Courses (BBA, BCA, MCA, MCom, MSc, MA, etc.)
- Hostel Accommodations, Fees, and Amenities (e.g., Devadan Hall, Christ Hall)
- Examination Timetables, Evaluations, and Results
- Placement Guidelines, Training, and Campus Recruitment
- Library Resources, E-journals, and Remote Access (e.g., Shodhganga)
- Student Exchange Programs, Outgoing and Incoming Semesters
- Student Life, Incubation Cell, and Student Council Events (e.g., Daksh)
- Research Centres and Faculty Consultancy Projects

3. DETAILED COMPONENT-BY-COMPONENT BREAKDOWN
--------------------------------------------------------------------------------

[A] PREPROCESSOR (engine/preprocessor.py)
--------------------------------------------------------------------------------
The preprocessing module is the initial gateway for all user queries. It runs 
immediately when the user submits a message, preparing the text for matching 
and generating metadata for session analysis.

1. Text Normalization (normalize_input):
   - Strips leading and trailing whitespaces.
   - Collapses multiple consecutive spaces into a single space.
   - Applies Unicode NFC (Normalization Form Canonical Composition) normalization.
     This ensures that composite characters (common in Indian languages like 
     Malayalam, Tamil, and Kannada) are decomposed and represented in a standard
     canonical form for regex compilation and matching safety.

2. Language Detection (detect_language):
   - The chatbot supports Malayalam, Tamil, Kannada, Hindi, and English.
   - It performs language detection using character-by-character Unicode range 
     verification. Characters are matched against standard Indic ranges:
     * Malayalam: 0x0D00 to 0x0D7F
     * Tamil:     0x0B80 to 0x0BFF
     * Kannada:   0x0C80 to 0x0CFF
     * Hindi:     0x0900 to 0x097F
   - If 20% or more of the alphabetical characters in the query fall into one of 
     these script ranges, that language code is returned (e.g., 'ml', 'ta', 'kn',
     'hi'). Otherwise, it defaults to English ('en').

3. Intent Classification (classify_intent):
   - Categorizes user queries into specific domain areas: 'ADMISSION', 'HOSTEL',
     'ACADEMICS', 'EXAMINATION', 'PLACEMENT', 'EXCHANGE', 'LIBRARY', 
     'STUDENT_LIFE', 'RESEARCH', or 'GENERAL'.
   - This classification uses a keyword overlap score against dictionary lists.
     The category with the highest overlapping keyword count wins. It provides
     metadata tags on the dashboard UI.


[B] CONTEXT RESOLVER (engine/context.py)
--------------------------------------------------------------------------------
The Context Resolver manages state across multiple turns in a conversation, 
making the chatbot feel intuitive and human-like.

1. State Memory (ConversationContext):
   - Tracks a running list of message history, count of questions answered, the
     last matched Q&A database entry, and the last detected intent.

2. Vague Follow-up Query Resolution (resolve_followup):
   - Handles natural user behaviors like asking "What about the fees?" or
     "How to apply?" immediately after another query.
   - If the user's input is short (less than 6 words) and matches explicit
     follow-up phrases (e.g., "what about", "how about", "tell me more") or 
     vague keywords (e.g., "fees", "cost", "duration", "eligibility"), the 
     system enriches the query.
   - It extracts the primary noun keyword (word length >= 4, excluding common
     stop words) from the last matched database question (e.g., "hostel" or
     "BCA").
   - It prepends this topic to the current query, modifying "what about fees?" 
     into "hostel what about the fees?". This enriched string is then passed to 
     the matchers, ensuring it matches the correct hostel fee rules.

3. Repeat Question Detection (is_repeated_question):
   - Checks if the current matched entry is the same as the previous turn's entry.
   - If so, it adds a polite prefix ("As I mentioned earlier:

") to prevent
     redundancy.

4. Session Statistics (get_session_summary):
   - Activated when a goodbye intent is triggered.
   - Summarizes user interaction statistics and lists the top 5 key topics
     searched in the session by filtering out stop words from the query history.


[C] PATTERN MATCHERS (engine/matcher.py)
--------------------------------------------------------------------------------
The core matching intelligence consists of two levels of matchers and a fallback.

1. Level 1: Regex Matcher (RegexMatcher - Primary Engine, Confidence: 85%-100%):
   - Compiles all regex patterns from JSON files once during engine startup.
   - Executes search-based matching (re.search) against the enriched user query.
   - Longest Match Specificity: If multiple patterns match, it ranks them by the
     length of the matched substring. The longest matched substring represents 
     the most specific user query, which overrides more generic patterns.
   - Confidence Scoring: Matches are scored as:
       coverage = length_of_matched_substring / length_of_user_query
     This coverage ratio is linearly scaled to the [85%, 100%] range:
       confidence = 0.85 + (coverage * 0.15)
     This guarantees high confidence for queries matching predefined patterns.

2. Level 2: Keyword Matcher (KeywordMatcher - Fallback Engine, Confidence: 50%-84%):
   - Triggered only when the primary Regex Matcher fails to match.
   - Tokenizes the query and strips common English stop words (like 'is', 'the',
     'what', 'how').
   - Inverse Document Frequency (IDF) Scoring: Computes document frequency for 
     all terms in the Q&A database. Rare keywords (like 'Shodhganga' or 'Devadan')
     receive higher IDF scores, whereas frequent terms (like 'university' or 
     'courses') receive lower scores.
   - Scoring algorithm sums the IDF weights of query keywords that appear in 
     an entry's searchable text (which combines the question, English translation,
     and all sample queries).
   - Minimum Match Verification: To prevent false positives, it requires at
     least 2 keyword matches (or 1 match if the user query was a single word).
   - Confidence is computed as the ratio of overlapping IDF weights over the 
     total query IDF weights, scaled to the [50%, 84%] range:
       confidence = 0.50 + (raw_ratio * 0.34)

3. Fallback: Similar Questions ("Did you mean?" Recommendation, Confidence: 0%):
   - Triggered when both Regex Matcher and Keyword Matcher return no matches.
   - Uses Jaccard Similarity coefficient (intersection of words divided by union
     of words) between user input and entries' searchable texts.
   - Displays the top 3 closest matching questions in a "Did you mean?" list to
     help guide the user.


[D] RESPONSE BUILDER (engine/response_builder.py)
--------------------------------------------------------------------------------
The Response Builder structures context-aware answers using three main strategies.

1. Template + Data Rendering:
   - For parameterized answers, entries can contain an "answer_template" and a 
     "data" dictionary (e.g., BBA vs. BCA fees).
   - The Regex Matcher extracts entities using named capture groups:
     e.g., (?P<programme>bba|bca|mca)
   - The Response Builder grabs the captured group dictionary, normalizes the
     value, performs a case-insensitive lookup in the "data" sub-dictionary,
     and formats the template dynamically (e.g., substituting {fee} and
     {duration} details for BCA).

2. Conditional Answers:
   - Evaluates if the query has qualifying conditions (e.g., "boys hostel" or
     "girls hostel", "twin sharing" vs. "triple sharing").
   - Looks up conditions in "conditional_answers" by matching the extracted
     regex group values or checking keyword substrings in the query, returning
     the targeted answer variant.

3. Static Text Fallback:
   - Returns the direct static 'answer' string if no template or conditions exist.
   - For queries matched in Malayalam, Tamil, Kannada, or Hindi, it prepends the 
     original English translation header as a reference.

4. Follow-up Suggestions (get_followup_suggestions):
   - Automatically appends up to 3 interactive follow-up questions at the end
     of the response.
   - Priority 1: Explicitly linked questions listed in the "related_ids" key.
   - Priority 2: Questions belonging to the same academic/hostel category.


[E] CHAT ORCHESTRATOR (engine/__init__.py)
--------------------------------------------------------------------------------
The ChatEngine class coordinates the entire pipeline:
1. Load Q&A: Iterates and merges all JSON database files at startup.
2. Built-in Interceptors: Bypasses the matching pipeline for systemic queries
   using global regular expressions:
   - Greetings (e.g., 'hello', 'hi'): Returns a welcoming description of chatbot capabilities.
   - Thanks (e.g., 'thank you'): Returns a polite response.
   - Goodbye (e.g., 'exit', 'bye'): Clears state and displays the session statistics.
   - Help (e.g., 'help', 'menu'): Lists all available questions in the database.
3. Execution Loop: For normal inputs, runs Preprocessor -> Context Resolver -> 
   Regex Matcher -> Fallback Keyword Matcher -> "Did you mean?" suggestions ->
   Response Builder -> Context Update.
